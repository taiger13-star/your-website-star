## Development

Prefer working locally? You need Node.js and npm — [install with nvm](https://github.com/nvm-sh/nvm#installing-and-updating).

```sh
git clone <this-repository-url>
cd <repository-name>
npm i
cp .env.example .env
npm run infra:up
npm run db:migrate
npm run db:seed
npm run dev
```

## Каталог и админка

- PostgreSQL работает в Docker на `localhost:5450`. MinIO API — на `localhost:6300`, его консоль — на `localhost:6301`. Образ MinIO собирается локально из официального закреплённого исходного релиза, поэтому запуск не зависит от закрытого container registry MinIO.
- Настройки и локальные секреты находятся в `.env`, он намеренно не попадает в Git. Перед первым запуском замените значения администратора и сессии в нём.
- URL админки: `/admin/<ADMIN_ROUTE_TOKEN>`. Токен должен состоять ровно из 32 латинских букв, а вход дополнительно защищён `ADMIN_PASSWORD` и HTTP-only сессией.
- `npm run db:seed` переносит текущий демонстрационный каталог и изображения из `src/assets` в PostgreSQL и MinIO. После импорта данные для витрины берутся из БД.

## Аккаунты покупателей

- После `npm run db:migrate` доступны регистрация `/register`, вход `/login` и личный кабинет `/account`. Во временном режиме `AUTH_EMAIL_MODE=stub` после регистрации вводится код `0000`; письмо не отправляется. Такой код не подтверждает владение адресом почты, поэтому перед публичным запуском переключите режим на SMTP.
- Для реальной отправки писем задайте `AUTH_EMAIL_MODE=smtp`, `PUBLIC_SITE_URL` и `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` в `.env`. В публичной среде `PUBLIC_SITE_URL` должен быть HTTPS-адресом сайта. В SMTP-режиме почта подтверждается ссылкой и доступно восстановление пароля. Во временном режиме восстановление пароля отключено.
- Оформить новый заказ может только пользователь с подтверждённой почтой после входа. В кабинете видны только его заказы; старые гостевые заказы по совпадению почты автоматически не привязываются.
- Избранное гостя хранится в браузере и при входе объединяется с избранным аккаунта. Вкладка «Пользователи» в админке показывает также аккаунты с неподтверждённой почтой.
- Для проверки сценариев аккаунтов на локальной PostgreSQL с импортированным каталогом выполните `RUN_DB_TESTS=1 npx vitest run src/server/user-auth.integration.test.ts`. Тест перехватывает отправку писем и удаляет созданные тестовые аккаунты.

Полезные команды:

```sh
npm run infra:down     # остановить локальные контейнеры
npm run db:generate    # создать новую Drizzle-миграцию после изменения схемы
npm run db:migrate     # применить миграции
```

## Доставка СДЭК

- Пока доступ к боевому API СДЭК не выдан, оставьте `CDEK_MODE=mock`: поиск города, метки ПВЗ, стоимость и сроки будут возвращаться сервером как тестовые данные. В checkout они помечены как тестовый расчёт, а заявка всё равно сохраняется для ручного подтверждения.
- После получения доступа добавьте в `.env` `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET`, смените `CDEK_MODE=live` и перезапустите приложение. Секрет СДЭК не должен иметь префикс `VITE_`.
- Для `VITE_YANDEX_MAPS_API_KEY` нужен ключ продукта **JavaScript API** с настроенным ограничением **HTTP Referer**. Добавьте `localhost` для локальной проверки и домен сайта для публикации. Настройка ограничения может применяться до 15 минут; после замены значения ключа в `.env` перезапустите приложение.
- Город отправления задаётся `CDEK_ORIGIN_CITY_CODE`; по умолчанию это Москва (`44`).
- Перед подключением боевого API заполните в админке для каждого продаваемого варианта фактические параметры **упаковки**: длину, ширину, высоту и вес. Без них реальный расчёт СДЭК недоступен. В режиме `mock` для проверки оформления используется только тестовая оценка по размерам изделия.
- На checkout покупатель выбирает оплату доставки сейчас вместе с товаром или при получении. Товар всегда входит в сумму к оплате сейчас. Сервер перепроверяет цены товаров и тариф СДЭК; при изменении суммы требуется повторное подтверждение.
- Кнопка «Оплатить (тест)» сохраняет в заказе тестовый статус, **денег не списывает** и не создаёт отправление в СДЭК. Администратор вручную оформляет доставку, вносит номер отправления и после получения подтверждения СДЭК отмечает оплату доставки при получении. Если оплата тестовой заглушкой прервалась, покупатель может повторить её на постоянной странице заказа.
