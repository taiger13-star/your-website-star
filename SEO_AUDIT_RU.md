## Архитектура

React 19, TanStack Start/Router, Vite 8, Tailwind, Nitro Node server.
Основной HTML уже рендерится на сервере. Публичный каталог поступает из
PostgreSQL через `getPublicCatalog` и корневой loader; изображения — из
S3/MinIO. Статический `src/lib/catalog.ts` используется для начального
демо-наполнения, а не заменяет рабочую БД. Маршруты файловые в `src/routes`.
Инструкция AGENTS.md запрещает переписывать опубликованную историю Lovable;
force push/rebase опубликованной истории не выполнялись. Пользователь
подтвердил размещение на VPS; серверный release/менеджер процессов пока неизвестны.

### Правила индексации

- Основной адрес: `https://noir-atelier.ru`. Локальные адреса не попадают в canonical.
- В sitemap — только публичные статические разделы, коллекции и опубликованные
  товары с включённым вариантом. В тестовой БД это 38 адресов; на рабочей базе
  количество определяется её фактическим каталогом, а не зашито в коде.
- Sitemap пересчитывается при запросе; опубликование/скрытие товара учитывается
  без ручной сборки XML. Выдуманные lastmod/priority/changefreq не добавлены.
  При сбое БД возвращается ошибка, не фиктивная успешная пустая карта.
- `/catalog?collection=...` с одной коллекцией канонизируется на её страницу.
  Сортировка и рекламные метки не создают новые канонические страницы.
  Поиск, цвет, система, категория и сочетания фильтров — `noindex, follow`;
  значимые параметры остаются в их URL. Они не включены в sitemap.
- Корзина, оформление, аккаунт, избранное, вход/восстановление, заказы, admin,
  API/server functions и юридические служебные страницы исключены из индексации.
  Robots не используется как замена авторизации; страницы с noindex не закрыты
  Disallow, чтобы робот мог прочитать запрет.
- Неизвестные пути/товары/коллекции — 404. Публичный завершающий слэш — 308
  с сохранением параметров. POST и приватные адреса этим правилом не перенаправляются.

### Контент и разметка

Title/description централизованы в `src/lib/seo.ts`, названия и описания
товаров/коллекций берутся из действующего источника каталога. Добавлены ссылки
на коллекции, автополив и индивидуальный размер; раздел конфигурации ведёт к
реальным вариантам карточки и разработке нового изделия. Дубли страниц под
каждую формулировку запроса не создавались.

| Направление запросов | Основная страница |
| --- | --- |
| NOIR ATELIER, Нуар Ателье | `/` |
| Купить дизайнерские кашпо | `/catalog` |
| Кашпо с автополивом | `/smart` |
| Конкретная коллекция/изделие | `/collections/<slug>`, `/product/<slug>` |
| Кашпо на заказ по размеру | `/configurator` → `/3d-design` |
| Печать по своей модели | `/3d-printing` |

Organization содержит существующие контакты продавца; BreadcrumbList совпадает
с видимой навигацией. Product/Offer используют реальные SKU, изображения,
материалы и цену выбранного варианта. Для модели «скоро в продаже», у которой
в карточке нет покупки/цены, Offer не публикуется. Фиктивные наличие, оценки,
отзывы, гарантии, сроки доставки и скидки не добавлялись. Поля наличия в БД нет,
поэтому InStock не выдумывается. JSON-LD экранирует `<` и разделители строк.
Проверены JSON и согласованность полей; официальный Rich Results Test для
ещё не опубликованной версии не запускался.

Существующие сведения о размерах, материалах, уходе и получении заказа
сохранены в карточках и разделах. В статичных текстах главной и SMART исправлено
упоминание бокового окна на ранее подтверждённый вами верхний поплавок.
Убраны неподтверждённые обещания универсального литрового резервуара и подачи
«ровно в нужном объёме». Старые иллюстрации и два демо-описания всё ещё
показывают/упоминают окно: перед публикацией нужно сверить фотографии и эти
карточки с фактическими изделиями в рабочей БД. Новая фотография конструкции
не генерировалась вместо доказательства реального устройства изделия.

## Проверки

Проверки выполнялись на собранном Node/Nitro сервере, а не только в dev-режиме.
Для этого создан изолированный PostgreSQL 16.15 с официального источника EDB,
порт `127.0.0.1:5451`, база `noir_seo`, без Windows-службы. Применены штатные
миграции и демо-данные из репозитория; изображения обслуживаются локально.
Рабочая база/MinIO/SMTP/оплата VPS не использовались.

- `npm run build` — успешно.
- `npx tsc --noEmit` — успешно.
- `npm test` — 30 тестов пройдены; 17 интеграционных по умолчанию пропущены.
  Отдельный запуск интеграционных тестов аккаунтов и заказов с
  `RUN_DB_TESTS=1` — ещё 13 пройдены. Четыре теста загрузки файлов, требующие
  работающий приватный MinIO, не запускались; реальная отправка заявок и
  платёжные операции не выполнялись.
- `npm run lint` — 0 ошибок; 13 предупреждений существующих компонентов
  Fast Refresh/директив lint. Исправлена совместимость проверки окончаний
  строк с Windows, временная `.local/` исключена из lint.
- `npm run seo:check` — 38 canonical/200 URL, robots и три реальных 404.
- Расширенная HTTP-проверка — уникальные title/description, SSR H1, canonical,
  разметка для всех 38 URL, ещё 12 случаев параметров/служебных URL и редиректы.
- Реальное изменение статуса публикации в тестовой БД немедленно убрало товар
  из sitemap и дало 404. После возврата статуса карточка снова отвечает 200.
- Chromium: 19 проверок. Главная, каталог, коллекция, товар, конфигуратор и
  форма разработки открыты на 1440×1000 и 390×844; нет горизонтального
  переполнения, ошибок JavaScript и битых изображений. Проверены смена canonical
  при SPA-переходе, фильтры/поиск, размер, цвет, Standard/SMART, цена и корзина.
  В примере FLOW: 5600 → 11500 → 15600 ₽; в корзине 15600 ₽.
  Checkout без входа ведёт на login. Пустые формы не отправляются; все POST в
  браузерном тесте дополнительно заблокированы, фактических отправок — 0.
- Локальные лабораторные значения главной: LCP 416 мс desktop / 96 мс mobile,
  CLS 0,014 / 0,036; это один локальный прогон без мобильного ограничения сети,
  **не полевые Core Web Vitals и не прогноз скорости VPS**. Внешних ресурсов
  в проверенном localhost-превью нет. Изображения не пережимались и не уменьшались;
  основному фото добавлен высокий приоритет, размеры/дизайн сохранены.

## Аналитика, доступы и публикация

На проверенных публичных страницах счётчика и verification meta не найдено.
Подготовлены необязательные переменные Метрики/верификации и цели, без
выдуманных ID. Заявки засчитываются после успешного ответа сервера;
создание заказа отделено от оплаты, `mock_paid` не считается покупкой.

Присланный URL Вебмастера относится к HTTP-свойству и не содержит номера
Метрики. Его закрытый checklist через доступный веб-инструмент не открылся;
выводы о содержимом личного кабинета не делались. Нужны номер существующей
Метрики, подтверждение HTTPS-ресурса в Вебмастере/Search Console либо их
verification content, и сведения о настроенном SSH/развёртывании.

Порядок публикации, проверки доменов/сертификата и отката:
[deployment/SEO_VPS_RU.md](deployment/SEO_VPS_RU.md).
Публикация подготовлена, но сайт ещё не обновлён. Поисковые позиции и сроки
индексации не гарантируются; платные сервисы и покупка ссылок не использовались.
