## Что нужно перед публикацией

- Подтверждение владельца на выкладку. Ветка ещё не отправлена на GitHub.
- Настроенное SSH-подключение или имя хоста/пользователь, путь приложения,
  способ запуска (systemd, PM2 или Docker), активный nginx-конфиг и порт Node.
  Пароли и приватные ключи в чат передавать не нужно.
- Проверить актуальную серверную ревизию: если VPS содержит более поздние
  доработки, перенести этот коммит в отдельную ветку актуального исходника,
  разрешить конфликты и повторить сборку/тесты. Не заменять сервер старой веткой целиком.
- Сохранить текущий release, `.env`/EnvironmentFile, nginx-конфиги, дамп БД
  и сведения о резервной копии хранилища. Резервные копии содержат секреты,
  их нельзя класть в публичный каталог или Git.

## Порядок

1. В новом release-каталоге установить зависимости `npm ci` и выполнить
   `npm run build`, `npm test`, `npm run lint`, `npx tsc --noEmit`.
   Эта SEO-правка не меняет схему БД: новые миграции не нужны.
   **Не запускать `db:seed` на рабочей БД.** Тестовая база `noir_seo`,
   `.local/` и изображения на порту 8772 — только локальные фикстуры;
   на VPS их не переносить.
2. Использовать действующие DATABASE_URL, S3/MinIO, SMTP и сессионный секрет
   через существующий менеджер процессов. Новый Node release запускать
   сначала на отдельном loopback-порту с рабочими настройками только после
   проверки их назначения. Не заменять настройки доставки/оплаты тестовыми.
3. Запустить `npm run seo:check -- http://127.0.0.1:<порт-превью>`.
   Скрипт делает только GET: проверяет все URL sitemap, canonical, SSR и 404.
   Проверить каталог, карточку, конфигуратор и корзину без отправки заказов.
4. Исправить доменные редиректы по `seo-nginx.example.conf`, сверив его с
   действующей конфигурацией. Это шаблон с заполнителями, не готовый
   конфиг для слепой замены. Сейчас сертификат HTTPS www не подходит домену.
   Сначала обеспечить сертификат с обоими именами и проверить продление,
   затем настроить www → основной HTTPS-домен. Сохранить ACME и другие
   существующие служебные location. Выполнить `nginx -t` до reload.
5. После подтверждения переключить release/upstream штатным способом,
   перезагрузить только нужный процесс/nginx. Не выключать весь VPS.
6. Выполнить `npm run seo:check -- https://noir-atelier.ru` и проверить
   HTTP/HTTPS × www/без www с сохранением пути и параметров:
   три альтернативы должны перенаправляться на HTTPS без www;
   основной адрес должен отвечать 200. Проверить сертификат без `-k`.
   Путь, отсутствующий товар и коллекция должны возвращать 404, а не 200.
7. Только после успешной выкладки добавить
   `https://noir-atelier.ru/sitemap.xml` в Вебмастер и Search Console.
   Действия с этими аккаунтами требуют согласования. Присланная ссылка
   относится к HTTP-ресурсу; проверить наличие/главное зеркало HTTPS-ресурса,
   не удаляя HTTP-историю.

## Метрика и подтверждение прав

Нужны реальные значения, сейчас поля пустые:

| Переменная | Где взять |
| --- | --- |
| `VITE_METRIKA_COUNTER_ID` | Номер существующего счётчика Яндекс Метрики |
| `VITE_YANDEX_VERIFICATION` | Только content meta-тега подтверждения HTTPS-сайта в Вебмастере |
| `VITE_GOOGLE_SITE_VERIFICATION` | Только content meta-тега Search Console, если выбран этот способ; при DNS-подтверждении не требуется |

`VITE_*` встраиваются при сборке: после заполнения пересобрать release.
Проверить, что nginx/шаблоны не добавляют ещё один счётчик. Код не создаёт
повторный скрипт Метрики, если он уже есть. При пустом ID нет запросов Метрики.
В localhost-превью загрузка счётчика выключена. Настройки Яндекс Карт отдельные.

Цели типа «JavaScript-событие»: `add_to_cart`, `begin_checkout`,
`order_created`, `generate_lead`, `purchase`. Заявка засчитывается только
после успешного ответа сервера, создание заказа отдельно от оплаты.
`purchase` доступна только для сохранённого сервером статуса `paid`
у оплаты товара с провайдером, отличным от `mock`; повторный показ того же
заказа дедуплицируется в браузере. Нынешний `mock_paid` покупкой не считается.
Реальный платёжный провайдер в рамках SEO-задачи не подключался.
Имя, телефон, почта, текст заявки, файлы и личные URL в события не включены;
Webvisor, clickmap и автоматическое отслеживание ссылок выключены.

## Откат

При ошибке переключить upstream/release на сохранённую рабочую версию и
штатно перезапустить только процесс приложения. Вернуть сохранённый
nginx-конфиг, проверить `nginx -t`, выполнить reload. БД эта правка не
мигрирует, обратные SQL-операции не требуются. При необходимости откатить
SEO-коммит обычным `git revert` в новой ветке. Не использовать force push,
reset рабочего сервера или перезапись истории Lovable.
