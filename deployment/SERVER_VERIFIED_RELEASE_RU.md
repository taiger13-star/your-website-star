Публичная проверка с обычным доверием TLS:

Те же результаты получены для `/catalog?utm_source=seo-release-check`:
основной HTTP-редирект сохраняет путь/query; www не работает.
Срок основного сертификата — 30.09–29.12.2026: проблема www именно в SAN.

Готовы два этапа одного нового vhost `noir-atelier-www-seo`:

1. [HTTP-кандидат](candidates/noir-atelier-www.http.conf) для www: редирект
   расположен в `location /`, чтобы точный ACME challenge существующего
   nginx-authenticator мог сработать. Проверить `nginx -t`, затем reload.
2. Выпустить **отдельный** www-сертификат существующим Certbot и его текущим
   ACME-аккаунтом, не расширяя/заменяя основной сертификат:

   ```sh
   certbot certonly --nginx --cert-name noir-atelier-www-seo-20261104 -d www.noir-atelier.ru
   ```

   Идентификатор аккаунта взять из сохранённых действующих renewal-настроек
   и явно выбрать этот аккаунт; не регистрировать новый. Имя lineage сейчас
   свободно, перед запуском проверить повторно. nginx-authenticator временно
   меняет конфигурацию для challenge: сохранить её перед этим и сравнить после
   cleanup; конфиги других сайтов должны остаться прежними. Основной upstream
   на этом этапе остаётся 3100.
3. Только после реального появления сертификата применить
   [HTTPS-кандидат](candidates/noir-atelier-www.https.conf). Проверить SAN,
   цепочку, `nginx -t`, reload, доверенный TLS и редирект с сохранением URI.
   Проверить запись продления, существующий timer и ограниченный dry-run
   **только** новой lineage; не запускать общее продление других сайтов.

Используется обнаруженный nginx-authenticator, не предполагаемый webroot.
Резервирование до его запуска соответствует [инструкции Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html#nginx).
Ни выдача сертификата, ни reload сейчас не выполнялись.
